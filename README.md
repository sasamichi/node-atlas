# Node Atlas 公開用サイト（生成物）

- 本番Googleシートのデータから生成したサイト一式。生成元データ：CNT 250件、RGN 5,323件、NODE 228件、SEG 210件、LINE 112件、SYS 5件、OPR 30件、SVC 1件、STP 7件、REL 6,085件、検索 5,919件。生成スクリプトは hidden_files/site_build.py（シートからJSONを書き出して実行）。
- 構成（2026-11-03に JS表示方式へ移行）：静的ページは index.html（検索）+ search-data.js、countries.html、countries/<alpha2>.html ×250、hakodate.html、transport.html、lines.html、nodes.html、about.html。詳細ページは1件ずつ生成せず、ビューア（region.html / line.html / node.html / service.html）が data/ 配下の国別JSON（regions-<CC>.json など）を読み込んでブラウザで描画する。拠点の個別ページはこの移行で新設された。旧来の regions/・lines/・services/ ディレクトリは廃止。
- スタイルの約束：背景は白に固定する（body に background:#fff と color:#222 を明示）。検索窓などのフォーム部品も背景・文字色・枠線を明示する（input は background:#f5f5f5、color:#222、border あり）。ダークモード環境でも見えるようにするため。再生成時も必ず入れること（2026-11-02 ユーザー指摘で追加）。
- KR・ZW の国ページには、要確認データへの注意書きと「（要確認）」表示が入る仕様（RGNの notes に「要確認」を含む行が対象）。
- 2026-11-02 更新：日本のページに北海道の振興局・市区町村・郡・札幌市の行政区のセクションを追加（RGN 5,045→5,323件、検索 5,385→5,663件）。函館本線ページに各拠点の所属自治体（札幌市内は区まで）の列を追加。国ページ末尾の「地域データの出典」注記は維持すること。
- 2026-11-03 更新：詳細ページをJS表示方式に移行（ユーザーの指摘「1件ずつHTMLを作ると将来膨大になる」への対応）。ファイル数は 698 → 466 に減少し、全地域5,323件が詳細表示の対象になった。詳細URLは region.html?id=… 形式に変更（旧URLは無効）。
- 2026-11-03 更新（ページ構成の本番反映）：テストページで決めた構成を全ビューアと国ページに反映した。詳細は生成スクリプト冒頭のコメント（構成ルール）参照。要点：基本情報は全ページ表形式で所属もその中に入れる／文章のリード文は置かない／地域ページは都道府県＝振興局ツリー・市表・郡ツリー、振興局・郡＝表、自治体の拠点一覧は種別→路線の2段組（同名航路は両端ターミナルが同じ場合のみ統合、違えば事業者名を付ける）／路線ページは基本情報表・支線と運行系統・列車の独立セクション・駅表（名称・読み・コード・区間 km・累計 km・接続路線・自治体、距離は小数1桁で統一）／拠点ページは基本情報表・路線での位置（未収集区間は「途中駅未収集」と明示）・乗換・接続（路線名＋相手拠点名）・停車する系統・列車／国ページは基本情報表＋第一級地域のみ（日本の北海道特設セクションは廃止）。表形式のリストには list-controls.js によるリスト内検索と並べ替えを付けた（属性フィルターは保留中）。
- 公開頻度（2026-11-05ユーザー決定、同日に意味を明確化）：サイトの更新は原則1日1回。その日の作業がすべて終わってから、夕方〜夜にまとめて公開する（日中の区切りのタイミングでは公開しない）。余程のケースを除き、1日に複数回は公開しない。
- 公開時の注意（2026-11-03 実測）：GitHub連携の push-files は、スナップショット全体のサイズが約4.7MBを超えると HTTP 413 で失敗する（約4.0MBでは成功）。肥大化したら、まずペイロード削減を検討すること（実施済みの手法：JSONの最小化、表の共通スクリプト list-controls.js への分離、地域VMの名称・読みをID参照にしてクライアント側で解決、検索データの地域分を配列形式に圧縮）。
